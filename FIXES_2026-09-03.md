# Saraya Inventory — fixes

## Stock consumption
- End-of-shift closing stock now defaults to the real current front stock when a product was not edited.
- The worker UI initializes closing counts from the active shift's current stock.
- Adding stock during a shift updates the default closing count, preventing newly added stock from being falsely recorded as consumed.
- Finalization keeps `front_stock` equal to the physical closing count.
- Admin shift details calculate `Opening + Added - Closing = Consumed` and fall back to physical consumption when legacy metric columns are zero.

## Rami paper
Rami paper is intentionally separate from normal product/warehouse stock.
- Worker records opening count at shift start.
- Worker can add paper at any time with `Ajouter papier Rami`.
- Worker records closing count at shift end.
- Backend stores opening, added, closing and used counts per shift.
- Current paper stock and last-added timestamp/user are visible in Stock Management.
- Admin shift details show Rami paper usage.
- Database migration: `database/migration_rami_paper.sql`.
- Runtime schema safety is also included in the routes.

## Stock discrepancies
- The discrepancy table is created/updated safely if an older database is missing the review columns.
- Resolving a warehouse discrepancy now accepts the worker's physical count and updates `warehouse_stock` to `actual_quantity`.
- The resolution is logged.

## End-shift recording
- The end-shift recording stage is persisted so a worker can spend a long time counting cash.
- Cash counting progress survives refresh/reconnection.
- Finalization remains a separate action.
